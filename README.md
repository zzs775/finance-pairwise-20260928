# 大宗成交分配引擎 (Block Trade Allocation Engine)

把单一证券汇总订单的实际成交量，按各账户的**目标比例、整手倍数、最低/最高
获配和资格约束**分给最多 12 个账户，输出可逐笔复算的分配证明。仅使用 C++20
标准库，无任何第三方依赖；输入为本地文件或内置确定性合成实例。

## 构建

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

生成两个可执行文件：

- `build/block_alloc`：命令行工具。
- `build/selftest`：自动化测试（也可直接运行）。

## 使用

```sh
# 内置合成实例
build/block_alloc --synthetic

# 本地输入文件，同时把报告写到磁盘
build/block_alloc --input examples/block_feasible.txt --report report.txt

# 限制搜索节点预算，观察“预算耗尽（未证明最优）”状态
build/block_alloc --input examples/block_large.txt --node-budget 5000

# 运行全部自动化测试
build/selftest
build/block_alloc --selftest
```

参数：

- `--input <file>`：行式输入文件（见下）。缺省时使用内置合成实例。
- `--report <file>`：把规范报告写入文件（二进制、固定字节序列）。
- `--node-budget <n>`：搜索访问节点上限，默认 1,000,000。
- `--oracle-budget <n>`：全枚举 oracle 的完整解组合上限，默认 5,000,000。
- `--synthetic`：显式使用内置实例；`--selftest`：运行测试。

## 输入格式

行式 `key: value`，`#` 起始为注释，账户块以 `account: <id>` 开始：

```
name: <实例名>
total: <总成交量>

account: A
target: 40        # 目标量（参与账户目标量之和记为 F）
min: 10           # 最低获配
max: 60           # 最高获配
lot: 10           # 整手倍数（获配必须是其倍数）
eligible: yes     # no 表示剔除，固定获配 0
priority: 1       # 优先级，仅记录展示，不参与三层目标
prior: 30         # 上一次获配，缺省取 target
```

## 三层目标（严格字典序，绝不使用加权和）

设总成交量为 `T`，参与账户目标量之和为 `F`，账户 i 获配 `q_i`：

1. `d1 = Σ |q_i·F − target_i·T|`：比例绝对偏差分子之和
   （对应 `Σ |q_i/T − target_i/F|`，统一到整数分子口径）。
2. `d2 = max_i |q_i·F − target_i·T|`：最大单户偏差。
3. `d3 = Σ |q_i − prior_i|`：相对上一次分配的再分配变动量（换手）。

按 `(d1, d2, d3)` 严格字典序最小化；三者完全并列时，取**账户 ID 升序下
字典序最小的获配向量**。账户输入顺序、约束书写顺序或内部遍历顺序改变时，
结果与报告逐字节一致（账户一律先按 ID 规范化排序）。

## 校验与最小冲突账户集合

先做可分配量与约束一致性校验：逐户整手对齐后的有效区间、最低量之和、最高
量之和、整手 gcd 整除性、资格。不可行时返回按“账户数最小、ID 升序”裁决的
最小冲突账户集合：放松这些账户的下限/上限/资格（视为无约束松弛账户）即可
恢复可行，并在报告中列出全部触发原因。

## 搜索、剪枝与预算

- 在整数手空间（每户 `lo, lo+lot, …, hi`）上深度优先搜索，遍历顺序固定。
- 前缀后缀区间剪枝：当前前缀后，剩余量必须落在后缀 `[Σlo, Σhi]` 且满足后缀
  整手 gcd 整除。
- 可复算目标下界剪枝：`前缀d1 + 后缀各户独立最小偏差和` 是任意补全的合法
  d1 下界；d1 严格更差即剪。d1 仅可能并列时，只依据**已固定前缀**（任意补全
  的确定性下界）对 d2/d3 剪枝——忽略总量耦合的后缀独立 d2/d3 不会被滥用为
  剪枝界。
- 受限账户余数重分：贪心初始解先铺整手最低量，再把余数逐手分给未封顶账户，
  按 d1 边际增量最小、ID 升序裁决，已达上限的账户不再获得余数。
- 每个界都能从“已固定前缀 + 后缀账户约束区间”直接重算。
- 超过节点预算时返回 `BUDGET_EXHAUSTED_INCUMBENT`（或无 incumbent 的
  `INFEASIBLE`），报告同时给出可复算下界与当前上界，**绝不**把当前解标记为
  最优。

## 全枚举 oracle

`brute_force_oracle` 对小规模实例逐手枚举所有满足总量/整手/上下限/资格的
完整解，按相同的三层字典序目标与 ID 升序向量裁决求最优，并在报告中做
`oracle_cross_check`（分配向量与目标值双重比对）。自动化测试对每个可行用例
都执行 oracle 交叉验证。

## 报告内容

规范文本报告包含：搜索状态与节点统计；可分配性结论与最小冲突集；三层目标值
与整数口径说明；可复算上下界及最优性结论；逐账户配额、绝对偏差、最低余量
（`min_slack`）、封顶余量（`max_headroom`）；并列裁决规则；受限长度的决策
路径（建初始界、剪枝、更新最优、预算耗尽）；oracle 枚举量与交叉核对；复现
命令。

## 测试覆盖

`src/tests.cpp` 覆盖：不可整除、账户封顶、最低量、资格剔除、并列最优裁决、

打乱后报告逐字节一致、解析往返与内置实例。
